# 《渡山海》Demo开发路线总览

> 状态：Demo任务结构已建立。任务台账以同目录下的 `Demo开发任务表.xlsx` 为准。

## 目的

本目录用于记录 Demo 的开发顺序、任务依赖、阶段验收门和预计工时。它和 `未确认暂定内容` 配合使用：暂定内容负责记录尚未获得策划确认的设计，开发任务表负责记录如何把当前 Demo 做出来。

## 任务规模

- 当前拆分：37项任务。
- 任务预计上限：单项不超过24小时。
- 暂定工时合计：约 198～397 小时，未包含正式美术制作的完整外包周期。
- 任务表中的实际工时、状态和备注由项目负责人维护。

## 开发阶段

| 阶段 | 里程碑 | 阶段目标 |
|---|---|---|
| 阶段0 Demo工程准备 | G0 Demo工程基线 | 工程目录、配置、场景和启动流程可用 |
| 阶段1 玩家战斗 | G1 玩家战斗可玩 | 角色能移动、普攻、闪避、释放技能和大招 |
| 阶段2 兽印与增益 | G2 构筑可用 | 兽印槽位、三选一奖励和检查点升级可用 |
| 阶段3 敌人与战斗内容 | G3 敌人战斗可用 | 普通敌人、精英和 Boss 能完成完整战斗循环 |
| 阶段4 地图与流程 | G4 Demo流程可通关 | 从起点到 Boss、失败和重试流程贯通 |
| 阶段5 UI与资源集成 | G5 Demo可交付 | HUD、交互、资源和验收完成 |

## 依赖原则

1. 先完成玩家战斗和最小敌人闭环，再扩展兽印和奖励。
2. 暂定设计全部配置化，策划确认后优先改配置和正式文档。
3. 正式美术未到位时可以使用占位资源完成程序和流程验收。
4. 完整版内容不自动加入本表；新增内容必须新增任务并重新评估工时。
