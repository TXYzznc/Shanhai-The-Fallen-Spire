# 多窗口暂停、抢占与恢复协议

本协议不改变项目权威计划优先级，也不授予扩大派发范围的权限。

## 暂停级别

- **局部暂停**：仅停止一个派发；负责窗口在自身派发/OpenSpec 记录恢复条件，点对点释放工具；未进入 Git 集成队列的请求直接撤回。不能形成有效检查点的未提交现场仍由原窗口保留目录锁。
- **批次暂停**：停止依赖同一公共结论的派发；制作人记录影响链，重新讨论并确认契约后才恢复。
- **项目级暂停**：停止所有写入，仅诊断和恢复；适用于工程不可用、数据/引用损坏、框架核心意外修改或 Git 归属无法判定。仅用户或制作人可解除。

## 抢占严重度

| 级别 | 定义 | 调度规则 |
|---|---|---|
| S0 | 工程不可用、数据损坏或阻塞全部窗口 | 经用户或制作人批准可抢占 |
| S1 | 阻塞当前批次、阶段门或关键验收 | 制作人调整批次，不自动抢占 |
| S2 | 局部缺陷且有替代路径 | 回原实现窗口排队修复 |

抢占前必须获得批准、记录最后有效提交和未提交范围、释放工具并确认 Git 集成窗口未处理该现场，且保证不扩大原派发范围。共享工作区不得以 `git stash` 作为窗口现场交接机制。

## 最小交接与恢复门禁

暂停窗口回传派发 ID、OpenSpec、原因、严重度、依赖、恢复条件、最后有效提交、未提交修改状态、资源状态、Git 集成请求状态和接手建议。

恢复前，相关窗口必须确认阻塞已消失、派发与 OpenSpec 仍有效、写入/工具占用已点对点确认、目标工具可用、编译或必要引用检查通过且恢复点可识别。若需要提交，Git 集成窗口还须确认暂存区无他人内容。批次/项目级恢复由制作人更新中央状态；若需要改变已确认契约，保持暂停并重新进入方案讨论。
