# Git 集成窗口工作流

`git-integration` 是共享主仓库唯一的常规 Git 暂存与提交执行窗口。它是执行队列，不是方案审批者、范围授权者或制作人替代者；所有窗口只提交、不推送。

## 职责

Git 集成窗口负责接收精确请求、只读复核派发/OpenSpec授权与工作区、显式暂存获批路径、复核差异和暂存清单、以中文提交并只向请求窗口返回结果。

它不得修改专业实现、补写测试、批准派发外路径、决定优先级或验收、推送、合并、变基、切换分支、改写历史，或清理归属不明的现场。

## 请求合同

每个可独立回滚且验证通过的工作单元，专业窗口向 Git 集成窗口发送：

```text
派发/OpenSpec ID：<id>
请求类型：Git 提交
精确路径：
1) <path>
验证结果：<tests-or-manual-evidence>
建议提交标题：<中文>
建议提交正文：<中文>
永久排除：<authority-sources-other-workspaces>
当前占用：<tool-and-write-scope-state>
授权依据：<dispatch-openspec-or-user-authorization>
```

缺少路径、验证、中文提交说明、排除项或授权依据时，集成窗口直接退回请求窗口补全，不找制作人代填。

## 提交门禁

1. 确认请求窗口、派发/OpenSpec 与精确路径一致，且路径在既有授权内。
2. 读取 `git status --short` 与 `git diff --cached --name-status`；暂存区必须可判定。
3. 复核请求路径差异和验证证据，再以 `git add -- <paths...>` 显式暂存；禁止 `git add -A`、`git add .` 和通配暂存。
4. 再次核对暂存清单完全匹配请求，运行 `git diff --cached --check`。
5. 使用中文标题、概要和正文提交；术语、文件名、类型名、派发 ID 与 OpenSpec change ID 可保留原文。
6. 只向请求窗口返回提交号、实际文件清单和索引释放状态。

## 退回与升级

路径清单、验证证据或中文说明不完整；请求窗口自身差异检查失败；或实现与证据不一致时，直接退回请求窗口。

路径授权或归属无法判断、只读内容混入且无法安全分离、仓库锁/HEAD/分支异常、需要新用户授权，或请求包含推送/合并/变基/切分支/改写历史时，停止 Git 操作并升级制作人或用户。

## 队列

- 按收到时间先进先出；S0 修复仅在用户或制作人明确批准后插队。
- 一次只处理一个请求；合格请求立即提交，不等待制作人二次批准。
- 普通提交不通知制作人；整个派发批次完成时由负责专业窗口汇总提交号并报告。
