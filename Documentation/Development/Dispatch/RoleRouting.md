# 多窗口职能与能力路由

长期用户可见工作窗口以稳定职能域组织，并声明优先 agent 职责与 SKILL 方向。窗口可以使用当前环境的可用能力完成必要检查；这不是对 `.claude/SKILL_MATRIX.md` 的权限扩张。只有被显式委派的子 agent 才受 agent 配置和 SKILL 白名单限制。

| 工作窗口 | 主要职责 | 优先 agent 职责 | 常见协作 |
|---|---|---|---|
| 制作人 | 范围、批次、依赖、派发、验收、归档 | `producer` | 所有专业窗口 |
| Git 集成 | 共享工作区暂存、提交、边界复核和结果回传 | 不建立常驻专用 agent；按工作流执行 | 所有需要提交的专业窗口 |
| 客户端 | Unity 架构、C#、Editor 工具、TA 接入 | `client-lead`、`client-unity`、`tools-engineer`、`client-ta` | 测试、制作人 |
| 后端 | 网络、服务、数据与部署 | `net-lead`、`net-backend`、`net-db` | 客户端、测试 |
| 测试 | 独立验证、缺陷定位、验收证据 | `qa-engineer` | 缺陷交回原实现窗口 |
| 美术 | 视觉方向、2D/3D、UI、动画、VFX 资源技术 | `art-director`、对应 `art-*` | 客户端、制作人 |
| 专项设计 | 项目领域规则、配置语义与验收输入 | 按任务组合既有职责，不新建框架常驻业务 agent | 制作人和对应技术/美术窗口 |

## 跨职能边界

- 窗口可完成轻量跨职能检查，但不得绕过派发范围、写边界或工具独占。
- 职责内用户决定影响其他职能时，提问窗口直接通知受影响窗口；无需制作人转述。
- 形成独立交付物、持续占用另一职责域、改变公共契约，或点对点协调失败时，必须升级制作人拆分派发。
- Git 集成窗口不修改实现或判断方案，只执行已有授权的提交合同。
- 专项设计是项目层窗口职能，框架不预设玩法、内容或产品领域 agent。
