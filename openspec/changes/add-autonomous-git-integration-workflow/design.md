## Context

框架已有派发、占用和 Git 索引短锁规则，但将日常提交授权交由制作人协调，且普通专业决策必须经制作人回传。来源实践显示，可由专业窗口在明确派发边界内自治，并把共享 Git 操作收敛给独立窗口，减少不必要的串行沟通。

## Goals / Non-Goals

**Goals:**

- 让专业窗口在任务、写入范围、冻结方案和验收边界内自主推进并直接同步受影响窗口。
- 让 `git-integration` 作为唯一常规暂存/提交执行窗口，严格核对授权与精确路径。
- 仅将异常、公共边界变化和整个批次验收升级制作人。
- 使审计读取 UTF-8 BOM 文件时稳定处理首行内容。

**Non-Goals:**

- 不自动创建窗口、决定优先级、扩大授权、推送、合并、变基或改写历史。
- 不迁入任何产品名、活动派发、真实窗口标识、端口、绝对路径或权威计划。

## Decisions

### Git 集成窗口是执行队列，不是审批者

专业窗口提交包含精确路径、验证证据、中文提交信息和排除项的请求；集成窗口仅在既有派发/OpenSpec授权内显式暂存、复核并提交。归属、授权或仓库异常无法安全处理时升级制作人或用户。

### 制作人只处理强制升级和批次完成

普通进度、单项用户决定、测试通过、增量归档和独立提交由相应窗口自行记录或点对点传递。范围、依赖、公共合同、共享资源异常、S0/S1和批次完成才升级。

### BOM 在文本边界统一剥离

框架纯度审计的 UTF-8 文本读取使用 `utf-8-sig`，避免 BOM 阻断锚定的首行解析。此选择不改变文件内容，也不扩大审计范围。

## Risks / Trade-offs

- [Git 集成窗口成为队列瓶颈] → 请求必须完整、单请求串行且无需二次制作人审批。
- [自治导致边界漂移] → 派发模板明确自治范围和制作人强制升级事件。
- [点对点通知遗漏] → 受影响面不明或协调失败必须升级制作人。

## Migration Plan

1. 添加 GitIntegration 模板并更新全部协作入口及派发规则。
2. 更新 producer 源配置，再由 `sync-agents.py` 生成 Codex 镜像。
3. 更新纯度审计和测试，运行同步、审计、OpenSpec 严格验证与 Python 测试。

## Open Questions

无；自治范围、Git 集成职责和升级边界已由制作人确认。
