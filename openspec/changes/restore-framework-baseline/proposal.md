## Why

当前仓库由已开发项目回迁而来，框架代码之外仍混有具体游戏业务的规格、工作流假设、SKILL 内容、测试证据、资源与生成物。若继续以此作为项目模板，新项目会继承错误的领域模型、路径约定和历史上下文，因此需要先恢复为不包含业务残留或样例的严格框架基线。

## What Changes

- **BREAKING**：删除当前工作树中的全部业务代码、业务资源、业务配置、业务规格、业务测试产物、业务编译生成物与业务历史说明；历史仅由 Git 保存。
- **BREAKING**：删除依赖具体玩法领域的 agent、SKILL、工作流和固定目录约定；不以“可能适用于某些游戏”为保留理由。
- 将必须保留的工程工作流、agent 和 SKILL 改写为领域无关、项目无关、路径可配置的框架能力。
- 建立框架基线清单、禁止内容规则、引用完整性检查和自动审计入口。
- 清除演示场景、示例 Prefab、示例数据、教学案例和验证样例；本次变更不补充任何新样例。
- 保留 Unity 2022.3.62f3、GF_X 核心、必要第三方依赖、通用构建/诊断/资源/输入/配置基础设施，但移除其业务实例和陈旧生成结果。

## Capabilities

### New Capabilities

- `framework-baseline-purity`: 定义纯框架基线允许保留的内容、禁止出现的业务内容、审计范围与验收门槛。

### Modified Capabilities

- `skill-governance`: SKILL 的保留标准从“游戏开发可能有用”收紧为“领域无关且属于框架/工程工作流”。
- `skill-routing`: agent 与 SKILL 路由不得绑定具体玩法领域、业务数据模型、项目名称或固定业务路径。
- `workflow`: 通用工作流不得携带业务阶段、业务制品、业务命名或教学样例。
- `unity-skills-routing`: Unity 自动化路由只保留编辑器与框架操作语义，不预设玩法对象、业务场景或业务资源。

## Impact

- 影响 `.claude/`、`.codex/`、`openspec/`、`tools/`、`Assets/`、`ProjectSettings/`、生成物与根目录文档。
- 需要重新生成 `.codex/agents/*.toml`，不得直接手工维护镜像。
- 会删除大量现有 SKILL、业务 OpenSpec、playtest 证据、截图/测试结果、热更 DLL 与 HybridCLR 业务生成结果。
- 清理过程中不得回滚或覆盖当前工作区中用户已有的迁移改动；所有删除都必须先归类并验证引用关系。
