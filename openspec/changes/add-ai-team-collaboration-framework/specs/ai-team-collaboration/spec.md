## ADDED Requirements

### Requirement: 框架提供可初始化的多窗口协作制品
框架 MUST 在 `Documentation/Development/Dispatch/` 提供领域无关的调度说明、角色路由、派发模板、占用模板、暂停恢复协议、窗口自动化规范、本机注册表示例与初始化指南。基线 MUST NOT 包含活动派发、真实占用或产品实例。

#### Scenario: 新项目初始化协作
- **WHEN** 项目采用框架协作机制
- **THEN** 制作人 MUST 能仅依据初始化指南创建本机注册表、空占用表和第一份派发单

### Requirement: 派发和占用遵守单一协调入口
制作人窗口 MUST 独占维护中央占用表；派发单 MUST 声明可写范围、高冲突文件、工具独占和 Git 索引短锁。其他窗口 MUST NOT 修改中央占用表，并 MUST 在未取得索引锁时避免暂存、提交、变基、合并、切换分支或重写历史。

#### Scenario: 并行窗口共享工作区
- **WHEN** 实施窗口准备提交已派发范围内的改动
- **THEN** 它 MUST 取得 Git 索引短锁、显式暂存授权路径并在提交后释放该锁

### Requirement: 跨窗口通信只请求制作人动作
自动派发 MUST 只发送最小启动信息，并在注册表无效、项目不匹配或发送失败时降级为手动派发。专业窗口 MUST 仅在阻塞、权限或锁申请/释放、跨职能依赖、阶段放行、中央状态更新、增量归档或暂停需要制作人处理时回传。

#### Scenario: 普通实施进度
- **WHEN** 专业窗口的进度不需要制作人采取动作
- **THEN** 该窗口 MUST 保留进度在本窗口且不得发送跨窗口广播

### Requirement: 暂停与恢复保留可交接现场
协作规范 MUST 定义局部、批次和项目级暂停，以及 S0 至 S2 抢占严重度、最小交接信息和恢复门禁。暂停或抢占 MUST 不扩大派发范围或自动改变人类权威计划。

#### Scenario: 共享工具冲突
- **WHEN** 窗口发现 Unity、DCC、目录或高冲突文件占用冲突
- **THEN** 它 MUST 暂停相关工作、保留现场并请求制作人协调，而不是接管或覆盖其他窗口改动

### Requirement: 权威计划与可编辑输入边界可配置
派发模板和初始化说明 MUST 参数化表达由人类或外部系统维护的权威计划、只读输入和 AI 可编辑输入，且 MUST NOT 硬编码工作簿、任务编号或产品路径。

#### Scenario: 项目声明外部计划
- **WHEN** 项目使用框架模板声明权威计划
- **THEN** 模板 MUST 允许项目填写计划来源和只读边界而不把该计划复制到框架基线
