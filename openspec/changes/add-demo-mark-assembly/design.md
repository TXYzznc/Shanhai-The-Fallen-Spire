## Context

当前装备组件只保存四个ID，奖励直接调用TryEquip，HUD为GF动态加载的uGUI预制体。输入集中在DemoInputSource并提供语义快照。当前没有统一界面暂停状态。具体功能见Docs/GameDesign/02-系统设计/07-兽印装配界面.md。

## Goals / Non-Goals

实现所有权与装备分离、自由装卸、四槽HUD和Tab入口，以及可复用的界面暂停计数。范围不包含通用物品背包、跨局存档、升级、拖拽、其他战斗数值重做或更换UI技术。

## Decisions

### 所有权与装配

局内兽印集合与四槽装备由运行时模型持有，配置只承载兽印定义与图标。装备验证必须确认兽印已经拥有。获取失败不改变奖励确认状态；重复获取只发配置货币。替换和跨槽移动一次提交最终状态，避免中间空槽造成重复属性调整。列表与HUD订阅变化，不通过每帧构建列表同步。

### 通用暂停管理器

采用纯C# GameStateManager管理登记、计数和状态；Unity适配层负责实际暂停与恢复。名称为实现规划，不代表类型已经存在。状态最小定义为Playing / Paused，现有重试及通关流程仍由本局控制器负责。

| 候选 | 优点 | 局限 |
|---|---|---|
| 各界面直接设置Time.timeScale | 实现最少 | 关闭一个界面可能提前取消其他界面的暂停，无法满足用户计数要求 |
| 仅暴露无所有者的全局整数增减 | 支持多界面 | 重复打开、销毁漏关闭或重复关闭会造成计数失衡，难以追踪 |
| 所有者登记、暂停计数、统一适配 | 满足计数要求，可去重和清理，纯逻辑可单测 | 需要界面生命周期适配和对称注销 |

选择第三项，使用现有事件与标准集合即可，不新增DI框架。

- RegisterWindow创建一个注册句柄，订阅界面的已打开/已关闭通知；注册本身不增加暂停计数。
- 同一登记从关闭变为打开时获得一份暂停请求；重复打开幂等。同一登记关闭时只释放自己的请求；重复关闭幂等。
- PauseCount表示仍有效的暂停请求数，通过登记持有状态维护，不允许外部任意改写整数。计数大于0则Paused，归零则Playing。
- Unregister / Dispose解除监听，同时释放该登记未释放的暂停请求；销毁、禁用、池回收和HUD解绑均走此路径。
- GameStateChanged通知包含只读的前后状态与当前计数；只在实际状态变化时发状态通知。计数查询不会触发事件。
- 会话注入同一个管理器给HUD及玩法对象；不使用静态全局实例，不通过场景查找获得依赖。初始化时只绑定，不在依赖尚未就绪时广播。
- GF表单可在OnOpen / OnClose适配，HUD内部弹窗可在Show / Hide适配；实际可见性和暂停请求必须同步，而非只监听整个HUD是否打开。
- 通用适配允许后续界面通过“打开时暂停”配置注册，不把兽印类型写入管理器。
- 所有游戏暂停入口均经管理器登记，不混用直接Time.timeScale写入和请求计数。

### 暂停的实际影响

Unity适配在0→1时保存原时间倍率并暂停，在1→0时恢复原倍率；中间请求释放不恢复。界面使用不受战斗时钟影响的输入与UI更新。仅设置时间倍率不足以阻止Update中的即时攻击、伤害或闪避，输入和战斗入口还需消费统一暂停状态，避免零deltaTime仍结算一次伤害。

注册句柄与会话生命周期对称。正常退出先关闭/注销界面，再释放会话适配；不得由一个界面单独重置全局计数。会话整体释放时清理属于本会话的请求并恢复适配层持有的时间倍率，旧界面后续重复释放不会影响新会话。

### 界面与输入

弹窗采用已拥有列表、四槽区和详情区；选中仅预览，操作按钮提交，卸下保留所有权。HUD紧凑显示四槽图标，效果说明收进弹窗。奖励首次获得只加入集合，重复转币，奖励中无槽位操作。三选一保持现有双击确认语义。

Tab和Esc增加到现有语义输入快照，经输入边界采集；UI通过注入的provider消费。暂停时快捷关闭仍能使用，战斗操作屏蔽。装配界面与奖励/结算界面互斥，但通用管理器仍支持多界面同时持有暂停，以便后续界面叠加。

### 待定输入

重复兽印兑换数量必须为可配置正整数，正式数额尚未由用户指定。正式图标资源可替换；奖励、列表、槽位和HUD必须使用同一配置图标。

## Validation

纯逻辑测试覆盖两界面分别关闭、重复开关、注销未打开界面、销毁已打开界面、事件变化与非负计数。兽印测试覆盖未拥有禁止装备、首次获取不装备、替换保留、跨槽唯一性、卸下、复活保留及重试清空、重复兑换仅发一次。Unity集成测试覆盖暂停期间输入与战斗不结算、冷却冻结、UI仍可关闭、原倍率恢复及HUD退出无残留暂停。实机测试由用户执行。
