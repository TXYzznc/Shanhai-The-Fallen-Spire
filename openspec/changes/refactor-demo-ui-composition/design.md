## Context

UGUI、GF.UI和Game.State已存在。HUD本身不承载玩法状态；但奖励模型及弹窗控制仍挂在HUD根。保留现有规则、双击确认、四槽摘要、Tab/Esc和最后暂停请求释放后恢复。

## Goals / Non-Goals

目标：代码和资源边界一致，独立窗口能按需加载、回收、重新绑定；HUD显示区可独立编辑。所有输入仍消费IDemoInputSource。

不改玩法数值、布局风格、UI技术栈、框架核心和Player验收归属。

## Decisions

| 候选 | 优点 | 代价 | 结论 |
|---|---|---|---|
| 只拆组件 | 改动最少 | 弹窗仍绑HUD资源和生命周期 | 不满足已确认资源拆分 |
| 独立Prefab，会话预创建 | 同步开关简单 | 常驻占用与创建成本，另管回收 | 未选 |
| GF.UI独立窗口+会话协调器 | 复用框架加载/对象池，资源边界清晰 | 需覆盖异步加载、取消与暂停交接 | 用户确认 |

显示分为Vitals、RunInfo、MarkSummary三个嵌套子预制体；HUD Form仅绑定/解绑。表现层另为常驻Form。会话协调器管理奖励模型、窗口请求和输入；玩法通过奖励展示接口访问，独立于具体View或HUD树。

窗口请求立即登记加载暂停；成功打开后交接给Form暂停生命周期，关闭/失败/取消释放。加载和已打开期间都禁止重复请求与冲突开窗；迟到回调不得绑定到退出后的会话。GF关闭时清空玩法引用、事件和选择状态，池复用重新绑定。

奖励确认后关闭窗口，仍保留选择模型供检查点读取；Boss完成提示等待奖励完成才打开。重试取消全部弹窗并清空提示；关闭窗口当帧沿用GamePauseController输入保护。

## Risks / Trade-offs

GF加载是异步的，测试必须等待打开而不能假设同步；失败/取消会影响UIParams池所有权，需要按框架源码实现。常驻显示拆分增加组件但不在Update分配临时集合。不声称此次提高帧率，主要改善维护边界。

## Migration Plan

编辑器PrefabUtility迁移，不手改YAML；先导出面板与子区并绑定，再移除HUD旧节点/组件。工具幂等且不污染当前场景。配置提供独立资源路径；旧生成器停止对新HUD写旧结构。更新现有测试并加独立窗口生命周期/失败/取消覆盖；不使用电脑控制。

回滚：恢复项目脚本及Prefab/配置快照，框架无迁移。
