# Agent 协作指南

主对话是 orchestrator；agent 是受职责和 SKILL 白名单约束的专业执行角色。

## 是否拆分

只有任务包含可独立交付的职责边界、明确依赖或显著并行收益时才拆分。单文件
修改、局部诊断、线性任务和高度内聚的实现保持单 agent。

## 编排规则

1. 每个子任务必须有明确输入、输出、文件所有权和验收标准。
2. 有依赖时先产出契约或骨架，再启动下游实现。
3. 并行任务不得修改同一文件或共享可变状态。
4. 主对话负责合并、冲突处理和最终验证。
5. 用户未明确要求子 agent、委派或并行时，不启动 sub-agent。

## 交回主对话

agent 遇到以下情况必须停止：

- 需要白名单外 SKILL；
- 需要跨职能决策；
- 缺少权限、MCP 或必要输入；
- 任务超出职责边界；
- 三轮内无法收敛；
- 触发设计、架构、重构或中大型变更门槛。

## 共享状态

多 agent 共享工作区，因此每个 agent 必须保留他人改动，不得回滚、覆盖或
重新格式化无关文件。实现型 agent 必须声明文件所有权。所有 Git 提交标题、概要和
正文描述必须使用中文；专业术语、文件名、类型名、派发 ID 与 OpenSpec change ID
可保留原文。不得改写历史提交，所有窗口只提交、不推送。

agent 列表与白名单见 [SKILL_MATRIX.md](./SKILL_MATRIX.md)。

长期用户可见工作窗口的职能路由、派发和占用规则见 [Dispatch](../Documentation/Development/Dispatch/README.md)。工作窗口可以使用当前环境的能力完成必要检查；只有显式委派的子 agent 遵守本文件、对应 agent 配置和 SKILL 白名单。中央占用表仅由制作人窗口维护，真实窗口注册仅保存在被忽略的 `.ai/dispatch/`。
