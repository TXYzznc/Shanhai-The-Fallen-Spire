# Unity/GF_X 工程约定

## 目录边界

- `Assets/Game/ScriptsBuiltin/`：GF_X 框架核心。
- `Assets/Game/Scripts/`：领域无关扩展和项目接入边界。
- 产品代码、内容资源、配置和生成物由具体项目另行建立，不进入框架基线。

### 资源目录骨架

框架使用按资源类型划分的浅层目录骨架。具体项目可以在这些根目录下继续细分，
但不得把角色、玩法、关卡或产品模块等领域目录预置到框架基线。

- `Animations/`：动画片段、Animator Controller 和 Avatar Mask。
- `Audio/`：音乐、音效和混音资源。
- `Materials/`：材质资源；统一使用复数，禁止新增旧目录 `Material/`。
- `Models/`：模型源资产。
- `Prefabs/Core/`：框架通用 Prefab。
- `Prefabs/Entity/`：由实体系统加载的 Prefab。
- `Prefabs/UI/`：由 UI 系统加载的 Prefab。
- `Shaders/`：Shader、Shader Graph 和通用渲染代码。
- `Sprites/`：Sprite 与 SpriteAtlas 源资源。
- `Textures/`：非 Sprite 纹理资源。
- `Timeline/`：Timeline 与 Playable 资源。
- `VFX/`：粒子、VFX Graph 和视觉效果资源。
- `Video/`：视频资源。

`HotfixDlls/`、`AB/` 和 `HybridCLRData/` 属于可再生构建产物，不作为空目录骨架提交。

## 依赖与初始化

- 依赖必须显式声明，初始化顺序不得依赖脚本执行顺序或隐式查找。
- 初始化阶段只建立状态，不发布依赖尚未就绪的事件。
- 生命周期必须有对称的初始化、取消和释放路径。
- 新依赖先验证现有包和标准库不能满足需求。

## 事件与通信

- 事件名称描述已经发生的事实，不表达命令。
- 事件参数使用专用引用类型，字段保持只读或初始化后不可变。
- 查询、命令和通知使用不同接口，不借事件系统隐藏同步依赖。
- 订阅必须可追踪并在生命周期结束时解除。

## 异步

- 异步方法以 `Async` 结尾。
- 禁止 `async void`，Unity 回调适配层除外且必须捕获异常。
- 异步操作必须接受取消信号并绑定拥有者生命周期。
- 线程切换必须显式，Unity API 只在主线程调用。

## 性能

- 不在 `Update`、`LateUpdate`、物理回调和高频事件中制造非必要 GC 分配。
- 避免每帧 LINQ、装箱、闭包、字符串拼接和临时集合。
- 性能结论必须以 Profiler 或可重复测量为依据。

## 资源与配置

- ScriptableObject 是配置载体，不是运行时数据库。
- 资源路径、标签和索引由配置提供，不在代码或 prompt 中固定。
- 生成物必须可再生；包含具体项目输入的生成物不得提交到框架基线。
- Unity 资产移动、重命名和删除必须维护 `.meta` 与 GUID 引用。

## 输入

- 设备读取集中在框架输入抽象边界。
- 上层实现只消费语义化输入，不直接查询键位或设备状态。
- 测试通过可替换 provider 注入输入，不提交产品操作样例。

## 编码

- 类型、方法和公开成员使用 PascalCase。
- 私有字段使用 `_camelCase`。
- 公共 API 保持最小；可变实现细节不暴露为公共成员。
- 不使用 `GameObject.Find`、`SendMessage` 或无约束 `Resources.Load`。
- 修改后必须完成编译、引用检查和适当层级的测试。

## 日志

- 日志必须包含稳定类别、动作、结果和必要上下文。
- 不记录凭据、令牌、个人信息或完整大对象。
- 错误日志保留异常类型和可定位信息，不吞异常。
